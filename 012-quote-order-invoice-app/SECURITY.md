# SECURITY — 認証・認可・アップロード・運用上の安全対策

## 認証
- パスワード：10〜200文字、scrypt（N=32768, r=8, p=1, 32byte, ソルト16byte）。比較は timingSafeEqual。存在しないメールでもダミー検証で応答時間を揃える。
- セッション：`crypto.randomBytes(32)` のトークンを `fd_session` Cookie（HttpOnly, SameSite=Lax, 本番 Secure, Path=/）。DBにはSHA-256のみ。30日、1時間ごとにスライド更新。
- ログアウト（当該端末）／すべての端末からログアウト。パスワード変更・復旧時は他セッションを失効。
- 復旧：復旧コード8個（1回限り・ハッシュ保存・再発行で旧コード無効）。運営者発行の再設定リンク（24時間・1回限り・トークンはハッシュ保存）。
- アカウント削除：パスワード＋「削除します」入力で全データを削除。
- 購入者コード：任意設定。ハッシュ保存・1回限り。

## 認可・データ分離
- すべてのクエリに `account_id = セッションのアカウント` 条件。IDは推測困難なUUID、形式不正は404。
- 他アカウントのIDを指定した場合は**存在有無を漏らさず404**。
- DBの複合外部キー `(account_id, id)` により、別アカウントの顧客・案件・請求への関連付けは制約違反になる。
- テスト：`tests/integration/security.test.ts`（顧客・案件・見積・請求・入金・添付・PDF・候補・割当・検索・一覧のID書換え）。

## CSRF・XSS・ヘッダ
- 更新系APIは独自ヘッダ `X-Requested-With: FreelanceDesk` 必須（クロスサイトのフォーム送信・単純リクエストを拒否）＋Origin検証（`APP_ORIGIN` と不一致なら403）＋SameSite=Lax。CORSは許可しない。
- React の自動エスケープ。`dangerouslySetInnerHTML` 不使用。
- ヘッダ：CSP（`default-src 'self'`、`script-src 'self'`、`object-src 'none'`、`frame-ancestors 'self'`）、X-Content-Type-Options、X-Frame-Options、Referrer-Policy、Permissions-Policy、本番HSTS、API応答は `Cache-Control: no-store`。

## 入力検証
- zod で全APIの本文・クエリを検証（文字数上限、日付形式、整数円、数量・税率の形式）。SQLはすべてプレースホルダ。LIKE検索のワイルドカードはエスケープ。
- 本文サイズ上限：JSON 3MB、添付 10MB+α、CSV取込 5MB、復元 300MB（環境変数）。

## アップロード
- 拡張子の許可リスト＋先頭バイト（マジックナンバー）で実体判定。保存MIMEは実体から決定。
- 拒否：実行ファイル実体（MZ/ELF/Mach-O/シバン）、危険拡張子（exe, js, html, svg, docm 等）、マクロ付きOffice（vbaProject）、一般ZIP、判定不能な形式。
- ファイル名の無害化（パス・制御文字・引用符除去、150文字）。Content-Disposition は RFC 5987。
- 配信：所有者確認付きAPIのみ。`private, no-store`、`nosniff`、PDF以外は `CSP: sandbox`。公開URLなし。
- 容量：1ファイル10MB、アカウント合計500MB。

## レート制限
- 全API：1IPあたり600回/分。ログイン・復旧：1IPあたり10分20回、1メール15分10回失敗。登録・デモ作成：1IPあたり1時間5回。
- 単一プロセスのメモリ内カウンタ（複数台構成時は要置換）。`TRUST_PROXY=true` 時のみ X-Forwarded-For を使用し、利用者が偽装できる先頭ではなく**右端から `TRUST_PROXY_HOPS`（既定1）番目**を採用。

## ログ・秘密情報
- リクエストログはメソッド・パス・ステータス・所要時間のみ（本文・Cookie・クエリ文字列は出力しない）。エラーログはエラー名とメッセージ先頭200文字のみ。
- 銀行CSVはブラウザ内で解析し、本文はサーバーへ送らない・保存しない。
- 秘密情報は環境変数（DATABASE_URL 等）。リポジトリに `.env` を含めない（.gitignore）。
- 再設定リンク発行ツールは画面出力のみ（ログファイルへリダイレクトしない旨を明記）。

## バックアップ復元の防御
- 復元先が空のアカウントであることを**展開前に**確認。
- ZIPはストリーム展開し、実際の展開バイト数で上限（保存容量＋100MB）を超えたら中断（zip爆弾対策、ヘッダの申告サイズは信用しない）。許可するエントリ名は `manifest.json` / `data.json` / `attachments/<UUID>` のみ。
- 列名は information_schema に存在するものだけ、テーブル名は固定リスト。全IDを新しいUUIDへ付け替え、**バックアップ内に存在しないUUIDへの参照は拒否**（他アカウントのIDの持ち込み防止）。DB側も複合外部キーで同一アカウント内参照を強制（002_integrity.sql）。
- 添付は実体を再判定（MIME）、サイズは実サイズで保存、ハッシュ照合、保存容量上限を適用。
- 復元後に件数・金額を照合し、不一致ならロールバック。

## 端末側
- ログアウト・アカウント切替時に、端末下書き（localStorage）とService WorkerのAPIキャッシュを削除。
- 共有端末では使用後に必ずログアウトするよう説明書に記載。

## FreelanceDesk クライアントポータル（お客様向け）
- 認証の分離：お客様は `/api/portal/*` のみ。Cookie `fd_portal`（HttpOnly・SameSite=Lax・Path=/api/portal・本番Secure）。運営者の `fd_session` とは相互に通らない。CSRF対策（独自ヘッダ＋Origin）は共通。
- 招待リンク：256bit乱数、DBは SHA-256 のみ（平文は発行直後の画面に1度だけ表示）。URLフラグメント（`#t=`）で渡すためサーバーログ・Referer に残らない。引換後は画面のURLからも消す。期限（既定14日・最大90日）、再発行で旧リンク失効、手動失効、アクセス停止、登録メール照合（5回失敗でロック）。招待の確認APIはメールアドレスを返さない。
- 認可：`services/portal.ts` の `clientProject()`（公開中・自分の案件・その案件の招待を使用済み・停止なし）を全ルートで通し、版・コメント・セット・写真・納品・ファイルは必ず案件IDと組で照合。他アカウント・他案件・非公開（準備中セット・非公開納品・内部ファイル）は 404（存在を明かさない）。全ルートのID差し替えテストあり（tests/integration/portal.test.ts）。
- ファイル配信：用途ごとの公開判定のうえ、既存添付と同じヘッダ（nosniff・sandbox CSP・no-store）。写真セレクトで「元ファイル名を表示しない」場合は API と Content-Disposition の両方で番号名（例 001.jpg）にする。Service Worker は `/api/portal/*` をキャッシュしない。
- 承認の改ざん防止：承認・修正依頼・版のファイルは DB トリガーで変更不可。承認はファイルの SHA-256 を記録。承認は電子契約・電子署名ではない（画面に明記）。
- レート制限：招待の確認・引換 1IP 10分10回、承認 1セッション 1分20回、コメント等 1セッション 1分30回（プロセス内メモリ）。
- 限界：メールアドレスを知る第三者がリンクも入手した場合は防げない（期限・失効・アクセス停止・使用回数の表示で運用）。

## FreelanceDesk ヒアリング（お客様の回答・ファイル提出）
- 認証・認可はクライアントポータルと同じ（`fd_portal`、`clientProject()`）。ヒアリングは案件IDと組で照合し、運営者が公開していない・中止したヒアリング、他案件・他アカウントのヒアリング／ファイル／追加質問は 404。全ルートのID差し替えテストあり（tests/integration/intake.test.ts）。運営者API（/api/projects/:id/intakes…、/api/intake-templates…）も他アカウントのIDは 404。
- お客様に返すのは質問定義（パック設定を除く）・回答・提出物・項目の状態・差し戻し理由・追加質問のみ。内部のレビューメモ、回答チェックの候補、Ready の内訳は返さない。
- アップロード：既存の実体判定（危険形式・実行ファイル拒否）に加え、項目の受付形式（拡張子）・拡張子と中身の一致・件数上限・10MB 上限。お客様のアップロードは本文を読む前にアクセス権を確認。お客様が削除できるのは確認前の自分の提出のみ。
- 回答は質問ごとに形式検査（メール・URL は http(s) のみ・日付・数値範囲・選択肢・文字数）し、不正な回答は保存しない。1回の保存は300問・1回答50,000字まで。
- 回答チェック（ルール判定）は外部送信なし。外部AI APIは統合していない。
- レート制限：回答保存・送信 1セッション 1分60回、ファイル提出・取消 1セッション 1分30回。
- 案件開始パック・提出ファイルZIPは運営者のみ（Service Worker もキャッシュしない）。

## 既知の制約・未実施
- 第三者による脆弱性診断は未実施（RELEASE_CHECKLIST で販売前に推奨）。
- 2要素認証なし（初版対象外）。
- 添付のウイルススキャンなし（実体判定と危険形式拒否のみ）。
- クライアントポータルの招待はメール送信を伴わない（運営者が手渡し）。メール照合は本人確認の補助であり、強い本人確認ではない。
