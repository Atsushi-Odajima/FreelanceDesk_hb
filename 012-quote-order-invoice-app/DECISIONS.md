# DECISIONS — 技術・データ・安全性の決定記録

各項目：決定／理由／代替案・影響。日付は 2026-09-28。

## 提供形態
- **決定**：販売者（運営者）が1環境をホスティングし、購入者はURLで登録して使うマルチテナント（1アカウント＝1事業者）。任意で「購入者コード」必須化（`SIGNUP_CODE_REQUIRED=true`、`npm run codes:create`）。
- **理由**：「利用者へNode.js/Docker/DB構築を要求しない」「URLアクセスで利用可能」。購入者コードで無関係な登録と費用増を防ぐ。
- **影響**：運営者に継続費用（OPERATING_COSTS.md）。複数スタッフ権限は対象外。

## 技術構成
| 項目 | 決定 | 理由 |
|---|---|---|
| 言語 | TypeScript（サーバー・画面・計算ロジック共通） | 金額計算を1実装で共有（`shared/calc.ts`） |
| 画面 | React 19 + React Router 7 + Vite 8、CSSは自前（UIライブラリなし） | 依存を減らし長期保守を容易に |
| API | Hono 4 + @hono/node-server | 軽量・Web標準・型安全 |
| DB | PostgreSQL 16、`pg` で**パラメータ化クエリのみ**（ORMなし） | 一意制約・行ロック・トランザクションで二重登録防止を確実に。SQLを監査しやすい |
| 検証 | zod 4 | 全入力をサーバーで検証 |
| TypeScript | 5.9.3（7.x系は採用見送り） | 周辺ツールとの互換性を優先 |

## 金額
- 金額は**整数円**（DBは bigint、JSは安全整数範囲内に制限：単価10億円・合計1兆円未満）。
- 数量・税率は**10進文字列**で保持し decimal.js で計算。数量は小数3桁、税率は小数2桁まで。
- 端数処理は「明細金額」「消費税（税率ごとに1回）」を書類ごとに選択（切り捨て/四捨五入/切り上げ）。詳細は CALCULATION_RULES.md。
- **税務・法令適合は保証しない**（源泉徴収税の計算、インボイス制度の記載要件の充足判定などは行わない）。

## データ・スナップショット
- すべての業務テーブルに `account_id`。`(account_id, id)` の複合外部キーで、別アカウントのデータへの関連付けをDBレベルでも不可能にした。
- 見積・請求は「親（quotes / invoices：固定ID・番号）＋版（quote_versions / invoice_versions）」構造。入金は請求の**親ID**に割り当てるため、訂正しても割当は維持。
- 確定時に宛名・発行者・明細・単価・金額・条件を `snapshot`(jsonb) に保存。PDF・画面表示の確定版はスナップショットのみから生成し、後のマスター変更の影響を受けない（DBの CHECK 制約で「確定版はスナップショット必須」）。
- 明細・調整は jsonb（行ごとに固定ID・`itemId`で品目参照）。書類種別ごとに明細テーブルを分けるより単純で、スナップショットとも同形。
- 請求番号は**初回確定時に採番**（下書き破棄による欠番を防ぐ）。見積番号は見積作成時、版はv1,v2…。
- 受注は「1案件に有効な受注1件」「1見積版に受注1件」を部分一意インデックスで保証。
- 1つの受注から作る請求書は原則1通。発行済み請求がある受注で「請求書を作る」と409（already_invoiced）を返し、画面で確認した場合のみ追加請求（分割請求）として作成（`allowAdditional`）。

## 冪等性（二重クリック・通信再送）
- 作成系は画面が発行する `requestId` を保存し、`(account_id, request_id)` 一意制約＋`pg_advisory_xact_lock` で同一requestIdの同時実行を直列化。再送は既存レコードを返す（採番の欠番も発生しない）。
- 状態遷移（確定・提出・受注）は自然キーで冪等：確定済みなら何もしない、同じ見積版の受注は既存を返す。
- 入金割当は requestId 一意、かつ支払行を `FOR UPDATE` でロックして未割当額超過を防止。
- 画面側も実行中はボタンを無効化（`AsyncButton`）。

## 入金・照合
- 入金状態は金額から導出（未入金/一部入金/入金済み/過入金＋期限超過フラグ）。チェックボックスは持たない。
- 過入金は許容して明示。差額を値引き・手数料に自動変換しない。
- 銀行CSVは**ブラウザ内で解析**（UTF-8/BOM・Shift_JIS、RFC4180準拠パーサ）。サーバーへは「日付・名義・入金額」のみ送信し、CSV本文は保存・ログ出力しない。
- 重複防止：取込内容のハッシュで同一CSVを拒否、行キー（日付|正規化名義|金額|同一内容の出現順）で期間重複CSVの既存行をスキップ。
- 候補は「残額一致」「名義一致（顧客名・振込名義）」でスコア表示のみ。**自動確定しない**。同点複数は「要確認」表示。

## 認証
- 自前実装：scrypt（N=2^15,r=8,p=1）、セッションはランダム32バイトのトークンをHttpOnly/SameSite=Lax Cookieに、DBにはSHA-256のみ保存。30日スライディング。
- 標準復旧：**復旧コード（8個・1回限り）**を登録時に表示。メール送信サービスを契約せずに復旧でき、費用ゼロ。復旧コードも紛失した場合は運営者が本人確認のうえ `npm run account:reset-link` で24時間有効の再設定リンクを発行。
- メールでのパスワードリセットは初版では実装しない（外部メールサービス契約・DNS設定が必要なため）。NEXT_STEPS に記載。

## 添付
- 既定はDB内保存（`attachment_blobs` bytea）。バックアップ1本で完結し、追加サービス不要。
- 許可リスト方式：拡張子＋先頭バイト検査。実行ファイル実体（MZ/ELF/Mach-O/#!）・HTML・SVG・マクロ付きOffice・一般ZIPは拒否。ブラウザ申告のMIMEは使わない。
- 配信は認証済みAPI経由のみ（所有者確認、`Cache-Control: private, no-store`、`nosniff`、非PDFは `CSP: sandbox`）。**公開URLは発行しない**。
- 上限：1ファイル10MB、1アカウント500MB（環境変数で変更可）。

## PDF
- サーバー側で pdf-lib により生成（A4縦）。端末差がなく、スマホでも同じPDFを保存・共有できる。
- **フォント：IPA Pゴシック**。当初 Noto Sans JP（OFL）を採用したが、pdf-lib/fontkit のサブセット化でグリフが欠落する不具合を実画面描画で確認（テキスト抽出テストは通過してしまう）。pyftsubsetでの事前サブセットでも解消しなかったため、サブセット化が正常なIPA Pゴシックへ変更。太字は重ね描きによる疑似ボールド。回帰防止として「埋め込みフォントのグリフ輪郭検査」をテストに追加。
- PDFはスナップショットのホワイトリスト項目のみから描画（内部メモ・内部ID・開発情報なし）。Producer/Creator は「Freelance Desk」。

## PWA・オフライン
- 手書き manifest + Service Worker。アプリシェルはキャッシュ、`GET /api/*` はネットワーク優先・失敗時のみ直近キャッシュ（`x-fd-offline` で画面に明示）。PDF・添付・認証・データ出力はキャッシュしない。
- **更新系はオフライン同期しない**。オフライン時は保存ボタンを無効化し、入力は端末下書き（localStorage）に保持。画面上で「端末下書き（未保存）」と「サーバー保存済み」を区別。再接続後の登録は同じrequestIdを使うため二重登録しない。
- ログアウト時に端末の下書き・APIキャッシュを削除。

## サンプルデータ
- 「サンプルデータで試す」は**別の一時アカウント（is_demo）**を作って架空データを投入し、24時間後に自動削除。本番アカウントには投入しない。

## コードレビュー対応（2026-09-28）
独立レビューで10件の指摘を受け、全件修正・回帰テスト追加（tests/integration/review-fixes.test.ts）：
復元時のzip爆弾対策／復元データでの他アカウントID参照の拒否＋複合外部キー追加／X-Forwarded-For 偽装対策／同一受注の二重請求防止／
復元添付のサイズ・MIME・容量再検証／請求下書き破棄のロック順（デッドロック防止）／一覧・集計の2000件打ち切り撤廃／
銀行CSV同時取込の直列化／顧客・品目CSV取込の冪等化／期限切れデモのセッション即時無効化。

## 運用
- ホスティング推奨：Render（Web Starter + Postgres Basic-256mb、約$13/月）。Dockerfile を同梱しているため他社PaaSにも移行可能。
- レート制限はプロセス内メモリ（単一インスタンス前提）。複数台構成にする場合は共有ストアへの置換が必要（NEXT_STEPS）。
- 自動テスト用のレート制限緩和は `RATE_LIMIT_RELAXED_FOR_TESTS` 明示時のみ。本番では設定しない。
