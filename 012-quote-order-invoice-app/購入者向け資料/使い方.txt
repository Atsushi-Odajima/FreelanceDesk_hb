 Freelance Desk　使い方
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【全体の流れ】
 顧客 → 案件 → 見積（v1, v2 …）→ 提出済みにする → この見積で受注 → タスク → 納品 → 請求書を作る → 入金を記録 → 完了

案件の画面上部には「次の操作」ボタンと、問い合わせ→見積→受注→作業→納品→請求→入金 の進行状況が表示されます。
迷ったら「次の操作」を押してください。

────────────────────────────────
1. 顧客・品目を登録する
────────────────────────────────
- 顧客：会社名・屋号（必須）、担当者、敬称、住所、電話、メール、標準の支払条件、振込名義、内部メモ。
  ・「振込名義」に銀行明細に表示される名義（例：ｻﾝﾌﾟﾙﾃﾞｻﾞｲﾝ(ｶ）を入れておくと、入金照合の候補が出やすくなります。
  ・取引（案件）がある顧客は削除できません。使わなくなったら「アーカイブ」してください。
- 品目：よく使う作業や商品（例：LPデザイン 50,000円/式）。見積の明細で名前を入力すると候補として選べます。
  ・品目の単価を変えても、確定済みの見積書・請求書は変わりません。
- CSVでまとめて登録：設定・データ → CSV取込（テンプレートは「CSVテンプレート」フォルダ）。

────────────────────────────────
2. 案件を登録する
────────────────────────────────
「案件を登録」→ 顧客を選ぶ（その場で新しい顧客も登録可）→ 案件名・問い合わせ日・予定納期 → 登録する。
- 入力途中の内容はこの端末に「端末下書き」として自動保存されます。登録するまでサーバーには保存されません。
- 通信が途切れてボタンを押し直しても、案件が二重に作られることはありません。

案件の状態：問い合わせ／見積作成中／見積提出／検討中／受注／作業中／納品待ち／納品済み／請求済み／完了／失注／キャンセル
- 見積の提出・受注・納品・請求の操作に合わせて自動で進みます。「状態を変更」で手動でも変えられ、履歴に残ります。
- 状態を変えただけでは、見積書・請求書は作られません。

────────────────────────────────
3. 見積を作る（版の管理）
────────────────────────────────
案件の「見積を作成」→ 明細を入力（品目・数量・単位・単価・税率・説明）。
- 数量は小数（例：2.5時間）も入力できます。
- 値引き・追加費用（交通費など）は「＋値引き」「＋追加費用」から。対象の税率を指定します。
- 税の表示（税抜・外税／税込・内税）、明細金額と消費税の端数処理（切り捨て・四捨五入・切り上げ）を選べます。
- 「保存」でサーバーに保存。画面右上の表示で「端末下書き（未保存）」か「サーバー保存済み」かが分かります。
- 「確定する」と、その版の宛名・明細・金額・条件が固定され、変更できなくなります。
- 内容を変えたいときは「この版をもとに新しい版を作る」→ v2 が下書きとして作られます。v1 はそのまま残ります。
  「変更メモ（社内用）」に変更理由を書いておくと履歴で確認できます（書類には載りません）。

見積書PDF：「見積書プレビュー」「見積書を保存」（スマホは「見積書を開く」「共有」）。
「提出済みにする」：顧客に見積書を渡した日と版を記録します。※このアプリからメールは送信されません。

失注：案件の「見積・受注」タブ →「失注にする」。請求書は作られません。

────────────────────────────────
4. 受注する
────────────────────────────────
見積の画面または案件の「見積・受注」タブ →「この見積で受注」→ 採用する版・受注日・納期を確認 →「受注を登録」。
- 採用した版の内容（明細・金額・支払条件）が受注として保存されます。
- 同じ見積で二重に受注されることはありません。
- 受注を取り消す場合は、先に請求書を取消してください。

────────────────────────────────
5. 作業（タスク）
────────────────────────────────
「タスク」タブで作業の区切りを登録（例：素材受領、初稿、顧客確認、修正、最終確認）。
期限・メモ・並べ替え（↑↓）・完了チェックができます。

────────────────────────────────
6. 納品する
────────────────────────────────
「納品」タブ →「納品を記録」→ 納品日・納品内容・顧客向けコメント・内部メモ。
- 「受注内容を納品書に記載する」にチェックすると、受注の明細・金額入りの納品書PDFになります。
- 記録後、その納品にファイル（写真・PDFなど）を添付できます。
- 納品を記録しても請求書は自動では作られません（ホームの「未請求」に表示されます）。

────────────────────────────────
7. 請求書を作る・訂正する
────────────────────────────────
「請求・入金」タブ →「請求書を作る」→ 受注内容（明細・金額・支払条件）と振込先が引き継がれた下書きができます。
→ 支払期限などを確認 →「確認へ進む」→ 内容を確認 →「確定して発行」。請求番号は確定時に付きます。
- 確定後は内容を変更できません。間違いがあれば請求書の画面で「訂正版を作る」（訂正理由は必須）。
  訂正前の請求書・訂正理由・旧金額・新金額・日時が履歴に残り、訂正前のPDFも見られます。
- すでに受け取った入金額より少ない金額には訂正できません（先に入金の割当を解除してください）。
- 誤って発行した場合は「取消」（入金が割り当てられている場合は不可）。
- 請求書PDFには内部メモなど社内向けの情報は載りません。

────────────────────────────────
8. 入金を記録する
────────────────────────────────
請求書の画面 →「入金を記録」→ 入金日・金額・方法。
- 残額より少ない → 一部入金、同額 → 入金済み、多い → 過入金 として表示されます。
- 過入金の差額を、自動で値引きや手数料として処理することはありません。
- 支払期限を過ぎても未入金・一部入金の請求書は「期限超過」になります（期限日の翌日から）。
- 入金を間違えた場合は、請求書の画面で「割当解除」、または 入金一覧 から削除できます。

────────────────────────────────
9. 銀行明細CSVで照合する
────────────────────────────────
請求・入金 →「銀行CSVで照合」
1) 銀行サイトからダウンロードした入出金明細CSVを選ぶ（文字コードは自動判定。文字化けしたら切り替え）。
2) 「日付」「名義（摘要）」「入金額」の列を指定（見出しから自動で推測します。必ず確認してください）。
3) 「未割当の入金として取り込む」…入金の行だけが取り込まれます（出金の行は対象外）。
4) 入金一覧 →「照合して割り当てる」→ 候補（残額と金額が一致、名義が顧客名と一致 など）を確認し、正しい請求書を選んで「割り当てる（確定）」。
- 候補は目安です。自動で確定されることはありません。同じ金額・名義の候補が複数ある場合は「要確認」と表示されます。
- 同じCSVは二重に取り込めません。期間が重なるCSVでは、取り込み済みの明細は自動でスキップされます。
- 銀行へのログイン、残高の取得、振込・返金などは行いません。CSVの内容はブラウザ内で読み取り、日付・名義・入金額のみを保存します。

────────────────────────────────
10. ホーム（ダッシュボード）と検索
────────────────────────────────
- 要対応：期限超過の請求／今月の支払期限／未割当の入金／未請求／今週の納期／納品待ち／見積の回答待ち
- 金額カード：見積中・受注・請求済み・入金済み・未入金残額 を別々に表示します（合計して「売上」とはしません）。
  期間（今月・先月・今年・期間指定）と、各カードの集計基準が表示されます。
- 検索：案件番号・案件名・顧客名・見積番号・請求番号で探せます。

────────────────────────────────
11. データの保存（CSV・バックアップ）
────────────────────────────────
設定・データ → データ
- CSV出力：顧客・品目・案件・請求一覧・入金一覧（Excelで開ける形式）。
- バックアップ：全データ（添付ファイル含む）をZIPで保存。月に1回以上、安全な場所へ保存してください。
- 復元：データが空のアカウントにのみ復元できます（新しくアカウントを作って復元）。復元後、件数と金額が自動で照合されます。

────────────────────────────────
12. アカウント
────────────────────────────────
設定・データ → アカウント：パスワード変更、復旧コードの再発行、ログアウト、すべての端末からログアウト、アカウント削除。
- パスワードを忘れたとき：ログイン画面「パスワードを忘れた」→ 復旧コードで再設定。
- 復旧コードも無くした場合：販売者へお問い合わせください（本人確認のうえ再設定用のリンクをお送りします）。

────────────────────────────────
13. FreelanceDesk クライアントポータル（お客様専用ページ）
────────────────────────────────
案件の画面 →「クライアントポータル」タブ。お客様（案件の顧客）が、ログイン登録なしで次のことをできる専用ページです。
 ・制作物（デザイン画像・PDF等）の確認、コメント
 ・FreelanceDesk 修正指示：画像の直したい場所にピン（番号）を置き、種類（変更／削除／追加／移動／変更しない／その他）と内容を書く
 ・修正の依頼、承認（※電子契約・電子署名ではありません。承認の記録として残ります）
 ・公開した納品（納品書PDF・納品ファイル）のダウンロード
 ・FreelanceDesk 写真セレクト：番号付きの写真から、タップまたは番号入力（例「001, 007、012」）で選んで送信

【準備】
1. 顧客情報にお客様のメールアドレスを登録しておきます（招待リンクの本人確認に使います）。
2. 「公開状態」を「公開中」にし、必要なら「お客様に見せる状況」「お客様へのご案内」を入力して保存。
3. 「制作物を追加」→「ファイルを提出（v1）」。直したものは「新しい版を提出」（v2, v3 …。旧版は残ります）。
4. 「招待リンクを発行」→ 表示されたリンクをコピーして、メールやLINEでお客様に送ります。
   ・リンクはこの時だけ表示されます。失くしたら「再発行」（古いリンクは使えなくなります）。
   ・お客様はリンクを開き、登録のメールアドレスを入力すると入れます（5回間違えるとリンクが無効になります）。
   ・有効期限は既定14日（1〜90日で変更可）。期限内なら同じリンクでPCとスマホの両方から入れます。
   ・見せたくなくなったら「アクセス停止」（入室済みの端末も見られなくなります）。公開状態を「公開終了」にしても見られなくなります。

【確認・承認の流れ】
- 版の番号（v1 など）を押すと、お客様と同じ画面で修正指示（ピン）・コメント・修正依頼・承認を確認できます。
  ピンへの対応が済んだら「対応済みにする」。「修正指示書を見る」で番号入り画像と指示の一覧を印刷（PDF保存）・テキスト保存できます。
- 承認は「最新の版」に対してのみ行えます。お客様が古い画面のまま承認しようとしても、新しい版があれば受け付けません。
- 承認を間違えた場合は運営者が「承認を取り消す」（理由を入力）。
- 案件の状態：受注後の案件では、版を提出すると「作業中」、すべての制作物が承認されると「納品待ち」に自動で進みます。

【納品の公開】
「納品」タブで納品を記録（納品書PDF・納品ファイルを添付）→「クライアントポータル」タブの「納品の公開」で、
承認済みの版を含めるか選んで「ポータルで公開」。お客様は納品書PDFとファイルをダウンロードできます。
公開中は納品記録の削除・承認の取消はできません（先に「公開を取り下げる」）。

【写真セレクト】
「写真セレクトを作成」→ 写真を追加（JPEG/PNG/GIF/WebP、1枚10MBまで、1セット300枚まで）→ 必要なら「ファイル名順に並べる」・番号の移動・削除
→「お客様に公開」。公開後は番号が変わらないよう、並べ替え・削除はできません（追加した写真は末尾の番号）。
お客様が送信すると、画面に「番号 → 元のファイル名」で表示されます。番号対応表CSV・選択結果CSV/テキストで書き出せます。
「元のファイル名をお客様に表示する」をオフにすると、お客様には番号だけが見えます。

【注意】
- 招待リンクはメールで自動送信されません（このアプリにはメール送信機能がありません）。
- 大きなファイル（10MB超）・ZIPでの一括ダウンロードには対応していません（お客様からのファイル提出は 14章「ヒアリング」で行えます）。
- バックアップには制作物・コメント・承認・写真セレクトが含まれますが、招待リンクは含まれません。復元後は招待リンクを再発行してください。

────────────────────────────────
14. FreelanceDesk ヒアリング／FreelanceDesk 案件開始パック
────────────────────────────────
仕事を始めるのに必要な情報（質問）とファイルを、お客様にクライアントポータルから回答・提出してもらい、
足りないものを確認して「案件開始パック」（制作担当・Claude Code などへの引き継ぎ資料）にまとめます。
見積前（問い合わせの段階）から使えます。

【準備】
1. メニュー「ヒアリング設定」（スマホは「メニュー」→「ヒアリングのテンプレート」）で、サンプル（Web制作・EC・SNS運用・動画・採用・
   コンサル・税務資料・不動産・汎用）を元にテンプレートを作成し、質問と必要なファイルを編集します（作らずにサンプルをそのまま使うこともできます）。
   条件分岐（例：「EC」を選んだらEC用の質問を表示・必須にする）は「詳細設定（JSON）」で編集します。
2. 案件の画面 →「クライアントポータル」タブで公開状態を「公開中」にし、招待リンクをお客様に送ります（13章）。

【ヒアリングの流れ】
1. 案件の画面 →「ヒアリング」タブ →「ヒアリングを追加」でテンプレートを選んで「作成」→「お客様に公開する」。
   ・作成した時点のテンプレートの内容が使われます（後でテンプレートを直しても、作成済みのヒアリングは変わりません）。
2. お客様はポータルの「ヒアリング（ご回答のお願い）」から回答し、ファイルを提出して「内容を送信する」。
   途中で「一時保存」して後から続きを入力できます。形式が正しくない回答（メールアドレスなど）は保存されず、赤字で表示されます。
3. 「ヒアリング」タブで、項目ごとに「提出 3/5」などの状況と足りないものを確認します。
   ・ファイルや項目は「承認」または「差し戻し」（理由はお客様に表示されます）。提出されただけでは「承認済み」になりません。
   ・関係のない項目は理由を入れて「対象外にする」。
   ・「回答をチェック」で、曖昧な回答（例：目的が「会社のサイトです」だけ）や矛盾の可能性（例：商品数10 と「全25商品」）を探します。
     結果は候補です。「お客様に質問する」「社内で解決」「却下」を選んでください（自動で回答を直したり、お客様に送ったりはしません）。
     お客様が「送信」したときにも自動でチェックします。
   ・追加の質問は「質問を送る」。お客様の回答は「元の回答に追記して解決」で回答欄に反映できます。
4. すべての必須項目が承認され、未解決の確認がなくなったら「内容を確認してサインオフ」で「Ready（開始可能）」になります。
   ・Ready の後で必須の回答が変わると、自動で Ready が解除されます（もう一度確認してください）。
   ・どうしても先に進める場合は、理由（5文字以上）を記録して Ready にできます（理由はパックにも記載されます）。
5. 「案件開始パックを作成」→ Markdown／テキストで保存、または画面でコピー。「提出ファイルをZIPで保存」で提出物をまとめて保存できます。
   パックの各行には出典（[q:質問ID]・[file:ファイルID]）が付き、未回答は「Unknown」、未確定のものは「Open Questions」に入ります。
   回答から作った「候補」であり、技術仕様や受入基準を確定するものではありません。
6. 作業を始めたら「開始済みにする（受付終了）」。お客様はそれ以降、回答・提出を変更できません。

【注意】
- お客様への連絡（メール・リマインド）は自動では送られません。公開したことや差し戻しはメール/LINE等でお知らせください
  （ポータルの「これまでの経過」には表示されます）。
- 提出できるファイルは1つ10MBまで、形式は画像（JPEG/PNG/GIF/WebP/HEIC）・PDF・Word/Excel/PowerPoint・テキスト/CSV・動画（MP4/MOV）です。
  Illustrator（.ai）は「PDF互換ファイルを作成」で保存したものだけ受け付けます。SVG・EPS・ZIP は受け付けません。
- 「回答をチェック」は決まったルールによる判定で、AI（外部サービス）には送信しません。
