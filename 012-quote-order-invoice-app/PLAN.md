# PLAN — 商品#012 Freelance Desk — 見積・案件・請求管理

問い合わせ→見積→見積改訂→受注→作業→納品→請求→入金確認を、**1つの案件（固定ID）** に紐づけて管理する販売用Webアプリ。
対象：フリーランス・個人事業主・小規模受託。ERP/会計/税務ソフトにはしない。

## 1. 全体構成（要約。詳細は DECISIONS.md / DATA_MODEL.md）

| 層 | 採用 | 理由 |
|---|---|---|
| フロント | React 19 + TypeScript + Vite 8 + React Router 7 | 安定・情報量が多い。SPA + PWA |
| API | Node.js 22 + Hono 4（@hono/node-server） | 軽量・型安全・Web標準API |
| DB | PostgreSQL 16（`pg`、パラメータ化クエリのみ） | トランザクション・一意制約で二重登録防止 |
| 検証 | zod 4（サーバー側で全入力を検証） | |
| 金額計算 | 整数円 + decimal.js（数量の小数） | 浮動小数誤差を排除 |
| PDF | サーバー側 pdf-lib + fontkit + Noto Sans JP（OFL）サブセット埋め込み | 端末差のない同一PDF。スマホでもDL/共有 |
| 認証 | 自前（scrypt パスワードハッシュ + DBセッション + HttpOnly Cookie） | 外部SaaS費用ゼロ・データを外に出さない |
| 添付 | DB内保存（`attachment_blobs`、既定）。容量上限・MIME/実体検証 | バックアップ1本で完結。無期限公開URLなし |
| PWA | 手書き manifest + Service Worker | 依存を増やさず挙動を把握可能に |
| テスト | Vitest（単体・結合＝実DB）、Playwright（E2E、モバイル/PC viewport） | |
| 配備 | Docker 1コンテナ（API が静的ファイルも配信）+ マネージドPostgreSQL。Render向け render.yaml 同梱 | 利用者はURLにアクセスするだけ |

利用形態：販売者（運営者）が1環境をデプロイし、購入者はURLで登録（任意で購入者コード必須化）。1アカウント＝1事業者。

## 2. 画面構成

- PC（≥1024px）：左サイドナビ、表形式一覧、案件は「一覧＋詳細」2ペイン、PDFはiframeプレビュー。
- スマホ（<768px）：下部ナビ（ホーム/案件/入金/顧客/メニュー）、カード一覧、1画面1目的、44px以上のタップ領域、`inputmode="numeric"`、PDFは保存/共有ボタン。
- 画面：ログイン / 登録 / 復旧 / ダッシュボード / 検索 / 案件一覧・詳細（タイムライン・見積・タスク・納品・請求・ファイル）/ 見積編集 / 請求編集 / 顧客 / 品目 / 入金（一覧・手入力・銀行CSV取込・照合）/ 設定（事業者・アカウント・データ）。

## 3. Phase別計画と受入条件

### Phase0：技術選定・最小PWA
- [x] 技術・料金・ライセンス確認（OPERATING_COSTS.md / THIRD_PARTY_NOTICES.txt）
- 受入：`npm run build && npm start` でURLアクセス可、manifest/Service Worker が登録される、PC/モバイルviewportで表示される（Playwright）。

### Phase1：認証・事業者・顧客・品目・DB・認可
- 受入：登録/ログイン/ログアウト/復旧コード/パスワード変更/アカウント削除。事業者設定。顧客・品目CRUD＋アーカイブ（取引ありは削除不可）。別アカウントのIDで404。

### Phase2：案件・タイムライン・タスク・添付
- 受入：案件CRUD、12状態＋履歴、タイムライン（問い合わせ→…→入金）、タスク（並べ替え・完了）、添付（上限・MIME/実体検証・実行ファイル拒否・所有者確認付き配信）。

### Phase3：見積版管理・計算・PDF・提出
- 受入：v1/v2/v3、確定版は上書き不可→複製編集、スナップショット、計算（小数数量・端数・値引・追加費用・税率別）、A4 PDF（日本語・複数ページ）、「提出済みにする」で日付と版を記録。

### Phase4：受注・納品・納品書
- 受入：「この見積で受注」でスナップショット、同一見積の二重受注不可（再送でも1件）、納品記録＋ファイル、納品書PDF、納品で自動請求しない。

### Phase5：請求・訂正・PDF
- 受入：受注から明細引継ぎ→確認→作成（冪等）、確定後は訂正版（理由・旧新金額・日時）、割当済み入金額未満への訂正は拒否、PDFはホワイトリスト生成（内部メモ非混入）。

### Phase6：入金・銀行CSV照合
- 受入：状態は導出（未入金/一部入金/入金済み/過入金＋期限超過）、複数入金、過入金明示、CSV列マッピング（UTF-8/BOM/Shift_JIS、引用符・カンマ・改行）、候補表示のみ（自動確定なし）、同一CSV/同一行の二重取込防止、割当の冪等性。

### Phase7：ダッシュボード・検索・CSV・バックアップ
- 受入：7種の要対応リスト、5種の金額カード（期間明示、合算しない）、横断検索、CSV出力（BOM・引用・数式インジェクション対策）、顧客/品目CSV取込、全データZIPバックアップ→空アカウントへ復元で件数・金額一致。

### Phase8：PWA/スマホ・E2E・セキュリティ・説明書・デプロイ
- 受入：E2Eシナリオ1〜5合格、320/375/430/768/1366pxで主要操作、セキュリティテスト、購入者向け資料、デプロイ手順、RELEASE_CHECKLIST。実機未確認事項は未確認として記録。
